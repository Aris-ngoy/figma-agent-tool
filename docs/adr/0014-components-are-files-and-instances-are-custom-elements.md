# Components are files in components/, and instances are custom elements

ADR-0005 settled on Components that are either Defined in the Design Project or Linked to Figma. A Defined Component is `components/<name>.html`, holding one `<component>` frame per variant. `data-variant="kind=primary"` names a variant, as Figma's variant names do, and `data-property="label"` on a text makes a text property. It pushes as a component set of those variants on the Screens Page (a lone component without variants). A Linked Component is `components/<name>.json` naming a component (or set) by `key` (a library's) or `id` (one in the Linked File). Screens use either as a custom element named after the file (`<app-button kind="secondary" label="Go">`, hence the hyphen), holding nothing, with attributes for its properties and `style` only for its place and size, like a Figma-owned Element. Instances are `INSTANCE` nodes: Push sets their properties, name, place and size, never their layers, and Pull reads those back, never the layers either. Overrides of an instance's own layers stay Figma-only, as non-link reactions do (ADR-0013).

Push sends every Component with every Push, before the Screens, so instances always find theirs and node IDs survive. A Defined Component has a Baseline like a Screen (`sync/components/`), its main component's edits merge into its file, and Push is refused while it has Unpulled Changes. For a Linked Component, Push records what it found (`sync/linked/`: node, key, properties), from which Check validates instances and Pull tells defaults from overrides. Its own design is never pulled. A Linked Component without auto layout can't hug, so an instance the Screen leaves unsized keeps its main component's size, and reads back as hugging.

## Consequences

- Pull writes only the properties an instance sets to something other than its default. Defaults depend on the Component, so each Screen's Baseline records the properties of the Components it uses (`components`), Figma's version of a Screen is read against the Components as their Baselines and records have them, and the merge writes a property Figma changed only where it differs from the Design Project's default.
- A designer's detached instance becomes plain elements in the Screen. The detached layers' keys are ignored (they may carry the Component's), and their node IDs go in the Baseline, so the next Push updates them in place rather than adding copies.
- An instance of a component that isn't one of the Design Project's becomes a Figma-owned Element, so Pull never drops it.
- Figma property names become attributes in lower case, with hyphens for spaces. A text property has one default in Figma, so every variant's text showing it must have the same text.
- Not yet: Components holding instances or Prototype Links, boolean and instance-swap properties on Defined Components, and Render of a Component on its own (the Preview lists them). Deleting a Component's file leaves its component set in Figma.
